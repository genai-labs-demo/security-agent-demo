DOM-based and Attribute-based XSS attacks

What are DOM-based and Attribute-based XSS?

These are advanced XSS variants that exploit different attack vectors:

  • DOM-based XSS: The vulnerability exists in client-side JavaScript code that manipulates the DOM using untrusted data from sources like URL parameters, without proper validation.
  • Attribute-based XSS: Malicious code is injected into HTML attributes (like href, src, or event handlers) allowing script execution through attribute manipulation.

Why They're Dangerous

These XSS variants are particularly dangerous because:

  • DOM-based XSS never touches the server, making it harder to detect with server-side security tools
  • Attribute-based XSS can bypass simple HTML encoding that only protects tag content
  • Both can execute arbitrary JavaScript in the victim's browser context
  • They can steal cookies, session tokens, or perform actions on behalf of the user

How to Fix It

For DOM-based XSS: Validate and sanitize all data from untrusted sources before using it in DOM manipulation. 

// ❌ VULNERABLE
const name = new URLSearchParams(window.location.search).get('name');
document.getElementById('greeting').innerHTML = 'Hello ' + name;

// ✅ SECURE
const name = new URLSearchParams(window.location.search).get('name');
document.getElementById('greeting').textContent = 'Hello ' + name;

For Attribute-based XSS: Properly encode data when inserting into HTML attributes and avoid using user input in dangerous attributes. 

// ❌ VULNERABLE
element.setAttribute('href', userInput);

// ✅ SECURE
if (userInput.startsWith('http://') || userInput.startsWith('https://')) {
  element.setAttribute('href', userInput);
}
