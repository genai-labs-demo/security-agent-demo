What is Command Injection?

Command Injection is a security vulnerability that allows attackers to execute arbitrary operating system commands on the server. When user input is passed directly to system command execution functions without proper sanitization, attackers can inject additional commands using shell metacharacters like semicolons, pipes, and ampersands to execute malicious code on the server.

Why It's Dangerous

Command injection can lead to:

  • Complete server compromise (executing any command with application privileges)
  • Data exfiltration (reading sensitive files like /etc/passwd, database credentials)
  • System manipulation (modifying files, installing backdoors)
  • Lateral movement (using the compromised server to attack other systems)
  • Denial of service (crashing the application or consuming resources)

How to Fix It

Never pass user input directly to shell commands. Use safe alternatives: 

// ❌ VULNERABLE (shell command with user input)
const command = `ping -c 4 ${userInput}`;
exec(command);

// ✅ SECURE (use libraries instead of shell commands)
const ping = require('ping');
const result = await ping.promise.probe(userInput, {
  timeout: 10,
  extra: ['-c', '4']
});

// ✅ SECURE (if shell is necessary, validate input strictly)
const validHostname = /^[a-zA-Z0-9.-]+$/.test(userInput);
if (!validHostname) {
  throw new Error('Invalid hostname');
}
// Use execFile instead of exec to avoid shell interpretation
execFile('ping', ['-c', '4', userInput]);
